在pop.css做本次sdk彈窗更新
SDK 登入彈窗：固定尺寸轉彈性比例（重構總結報告）
這次針對 #bookedmodal（SDK 登入彈窗）的重構，我們徹底解決了以往「尺寸寫死、小螢幕擁擠、大螢幕破版、旋轉無法置中」的痛點。以下是本次重構的 5 大核心改動與原理說明：

1. 核心單位轉換 (px 升級為 rem)
過去的作法： 彈窗內的寬度、高度、字體大小（font-size）、間距等，全部使用絕對單位 px 寫死。導致螢幕變大時，彈窗看起來很小；螢幕變小時，內容又會擠在一起。
現在的改變： 透過自動化腳本，將彈窗內所有的 px 數值等比例轉換成了 rem（例如將主容器改為 width: 8.09rem）。
帶來的優勢： rem 是一個相對單位，會跟隨網頁根目錄 (<html>) 的基準字體大小變動。因為您的 reset.js 已經寫好了動態縮放機制的底層，現在整個 SDK 彈窗能夠像一張具有彈性的向量圖一樣，不管在哪種解析度下，都能完美等比縮放，完全不破壞排版比例。
2. 解除共用外殼的「緊箍咒」(max-width 限制)
過去的作法： 所有彈窗共用的 .nte-pop .popCont 寫死了 max-width: 570px。這對於一般的文字彈窗沒問題，但 SDK 彈窗的 UI 設計原稿較為寬闊，被限制在 570px 內導致輸入框和按鈕嚴重被擠壓。
現在的改變： 專門針對 SDK 彈窗加上了 #bookedmodal .popCont { max-width: none; }。
帶來的優勢： 彈窗終於能真正展開到設計圖該有的比例，解決了「內容物看起來偏小、擁擠」的視覺問題，且完全不影響其他舊有彈窗的排版。
3. 無敵的「絕對定位置中」(突破 Bootstrap 干擾)
過去的作法： 依賴 Bootstrap 原生的 .modal-dialog-centered。但在手機版轉向（直轉橫）或視窗小於 576px 時，Bootstrap 會強行塞入撐高元素 (::before) 試圖把高度撐滿，導致旋轉後的彈窗嚴重偏移、掉出畫面。前幾次嘗試使用 display: flex !important 又導致了隱形外殼擋住首頁按鈕的 Bug。
現在的改變： 我們徹底捨棄了 Bootstrap 的排版干預，改用純 CSS 的絕對定位：
css

position: absolute !important;
top: 50% !important;
left: 50% !important;
transform: translate(-50%, -50%) !important;
帶來的優勢： 彈窗現在具備「防彈級」的置中能力。不管視窗怎麼縮放、手機怎麼旋轉，它都永遠鎖死在畫面的正中心，且關閉時能正常隱藏，再也不會擋住底下的按鈕。
4. 解決放大產生的「毛邊問題」(zoom vs scale)
過去的作法： 為了讓手機版彈窗更大，原本使用了 scale: 1.25。但 scale 會像拉伸圖片一樣強制把畫面拉大，導致按鈕邊緣和背景圖產生像素模糊（毛邊）。
現在的改變： 導入了 @supports 語法，針對手機版改用 zoom: 1.25，並保留 scale 給少數不支援的瀏覽器（如 Firefox）當作備用。
帶來的優勢： zoom 會要求瀏覽器以 1.25 倍的物理尺寸「重新繪製」整個彈窗。因此在放大的同時，邊緣依然保持極致銳利，完全消除了模糊感。
5. 移除了冗餘的 2K/4K 斷點
過去的作法： 為了顧及 2K 和 4K 螢幕，原本寫死了 @media (min-width: 2560px) 來強制 scale 放大。
現在的改變： 將 2K/4K 的放大媒體查詢全數刪除。
帶來的優勢： 呼應第 1 點，既然已經改用 rem 讓彈窗具備原生彈性，它本來就會隨著 2K/4K 螢幕的寬度自動等比長大。刪除這些多餘的程式碼，不僅減輕了維護負擔，也避免了「重複放大」導致的比例失衡。
💡 總結： 這次的改動將一個「寫死且依賴外力 (Bootstrap)」的彈窗，重構成了「具有自身彈性、且能適應任何環境」的現代化響應式組件。它現在與您的 reset.js 核心邏輯完美契合！
